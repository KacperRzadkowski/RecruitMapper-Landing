How It Works

Three inputs. One ranked list.

No magic, no black box. Here is exactly what happens to your data.

1

Upload your LinkedIn export

A standard LinkedIn Recruiter CSV. No reformatting, no cleaning. We parse it as-is and extract what is useful.

2

Describe what you are looking for

Upload a PDF of your ideal candidate profile and project context. We read it, structure it, and turn it into the reference point everything else gets measured against.

3

We find and read their GitHub

Where a GitHub account exists (or can be reliably inferred), we pull real activity: commits, pull requests, code reviews, languages used over time.

4

You get a ranked list, not a decision

Each candidate gets a score from 0–100 with a per-dimension breakdown. You decide who to call. The tool does not pretend to do that part.

What It Actually Does

Specific tools for a specific problem

Built for one job: sorting a candidate list by how well each person fits a role. Nothing more.

🔍

GitHub profile discovery

Most candidates do not link their GitHub on LinkedIn. We use name, company, and location heuristics to find and verify the right account via the GitHub API.

📊

Actual coding activity, not vanity metrics

Commit history, pull requests opened and reviewed, issues filed, languages used consistently over time. Stars and follower counts tell you very little about what an engineer actually does day to day.

📐

Vector embeddings, not keyword matching

We embed your ideal profile and each candidate's background into the same high-dimensional vector space, then measure cosine similarity. It is a well-understood technique that is genuinely good at capturing meaning across text.

⚖

You control what matters for this role

Domain expertise is not the same weight as soft skills for every position. Eight scoring dimensions. Experience, skills, domain fit, context alignment, achievements, weaknesses, and more, each independently adjustable.

⚡

Concurrent processing

All API calls run in parallel batches. A list of a few hundred candidates takes a few minutes, not an afternoon. No queue, no waiting room.

🔒

No database, nothing stored

Everything is processed in memory and discarded when the session ends. There is simply nowhere for the data to live.

🧪

Tested against real hiring outcomes

We did not just build something that looked reasonable on paper. The scoring weights were tuned against actual recruiting decisions. When the tool ranked someone highly and a recruiter independently agreed they were worth a call, we noted it. When it did not, we adjusted. The rankings are meaningfully better than a random order, and we can show you the reasoning behind that.

Privacy

We do not keep your data

Not a privacy policy promise. A consequence of the architecture.

🗑

There is no database

Candidate data lives in memory for the duration of the analysis and is gone when the session ends. We cannot leak what we do not store.

🚫

Not used to train anything

We are fully opted out of third-party AI provider training. Your candidates' data does not improve any model, ours or anyone else's.

🔐

Sessions are independent

Each run is isolated. Nothing from a previous analysis is available to the next one. There is no cross-session state on the server.

☁

Deployed on AWS ECS Fargate

Serverless containers with no persistent compute state between requests. Scales with load, leaves no footprint.
